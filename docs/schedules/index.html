Plans & stages

Job plans (cron, sweep, resume, pipeline, agents) are authored under plans: in recipe.yaml. Runtime state and logs live under artifacts/jobs/plans/. Stages are still nested full runs under stages/<name>/.

PrerequisiteA run folder with recipe.yaml

recipe.yaml · plans

Declare named plans next to the method. run is a verb (train, eval, hash, tool:name, stage:name). Pipelines use steps.

example 
family: tabular
method: linear
data:
  path: data.csv
  target: y
eval:
  metric: mse
 
plans:
  nightly:
    kind: cron
    every: 60
    run: train
  pipe:
    kind: pipeline
    steps: [train, eval]

Author plans in YAML or via SDK (aq.plan / @schedule) — same plans: block. Legacy jobs/plans/*.yaml still loads for names not already in the recipe. Init does not create jobs/plans/.

aq job plan

List plans from recipe.yaml. tick runs due cron/resume entries; run fires one now. aq schedule is an alias.

example 
$aq job plan
$aq job plan tick
$aq job plan run nightly
$aq schedule run nightly

aq stage

List, scaffold, train, or eval nested runs under stages/. (Folding stages into a YAML stages: segment is still TODO.)

example 
$aq stage init prep
$aq stage prep
$aq stage eval prep
$aq stage
