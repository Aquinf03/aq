axi

axi lives inside the train Unix: same cwd, same files, same verbs. On a TTY, run axi (separate package from the aq framework CLI). It is not a chat toy with a private filesystem.

Prerequisiteaxi provider configured · cwd is a train folder · aq on PATH (or AQ_ROOT)

axi / axi agent

Interactive agent chat (TTY). Uses tools that wrap aq verbs against this train — including fleet (aq_add, aq_launch, aq_jobs, …). Every mutating step shows an allow yes/no picker (file writes include a unified diff preview). Tool runs show → / running / ok|fail with command output. After remote jobs train|run|…, the agent should aq jobs wait <id> (polls until done; never hangs on logs -f). Reads (ls/status) skip the picker.

example 
$axi

axi ask <prompt>

One-shot answer without the interactive UI.

FlagDescription
-y / --yes Auto-approve mutating tools (writes, train, jobs, shell, …).
--json Emit { text, tools }.
example 
$axi ask "hash the data then train"
example 
$axi ask -y "run eval and summarize"
example 
$axi ask --json "what failed last run?"
